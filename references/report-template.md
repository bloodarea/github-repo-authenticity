# GitHub 项目真实性调查报告（模板）

**仓库：** `OWNER/REPO`（GitHub 原始链接）
**调查时间：** UTC / 本地时区
**审查基准：** commit SHA / 默认分支（可变）
**范围：** 元数据 / Star 时序 / 文件树 / 关键源码 / Release / 分发包 / 外部来源
**局限：** 403、404、配额、树截断、未执行代码、抽样不足等

## 1. 摘要结论

| 独立维度 | 判定 | 证据强度 | 关键原因 |
| --- | --- | --- | --- |
| 人气/Star 真实性 | 暂无显著线索 / 待调查异常 / 有较强交叉证据 / 证据不足 | 直接/间接/弱/未知 | … |
| 宣称功能与实际实现 | 有静态证据 / 部分支持 / 明显矛盾 / 未验证 | … | … |
| 项目来源与身份 | 多方印证 / 存疑 / 相互矛盾 / 未验证 | … | … |
| 供应链风险 | 覆盖内无明显线索 / 需复核 / 高关注 / 未扫描 | … | … |

**建议：** 正常谨慎使用 / 继续调查 / 暂缓安装并人工审查 / 证据不足。

## 2. 具体待核验声明

| README / 宣传声明（含来源） | 应当出现的证据 | 检查结果与固定 SHA 文件链接 | 判定 |
| --- | --- | --- | --- |
| 声明 A | 模块、入口、测试或发布产物 | 文件路径和行号 / 未能读取的原因 | 静态支持/部分/矛盾/未知 |
| 声明 B | … | … | … |

## 3. Star 与维护行为

分别写明 Star / Fork / Subscriber、时间范围、真实的增星时序来源或 **未取得时序**；列出至少一个合理非欺诈解释。不能把 `pushed_at` 当作增星曲线。

## 4. 来源及供应链

记录组织身份、原项目/上游、包发布者、tag/Release/commit 对应、安装脚本及依赖的证据。正则命中不等于恶意；缺少覆盖不等于安全。

## 5. 未验证事项与进一步调查

- 哪个核心主张当前无法证明？
- 若要获得更强证据，最低成本的下一步是什么？
- 若涉及动态执行，是否已取得用户许可且准备隔离环境？

**措辞原则：** 有异常 ≠ 已证实刷星；静态有文件 ≠ 功能运行正常；无告警 ≠ 安全认证。
